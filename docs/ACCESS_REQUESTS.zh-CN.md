# 访问申请与独立审批（alpha）

> [English](ACCESS_REQUESTS.md) | 简体中文

使用数据库权威模式及已有[人员登录](HUMAN_LOGIN.zh-CN.md)、浏览器配置。为申请人和
审批人分别配置稳定的 `principal:` ID：申请人使用 `role:requester`，审批人使用
`role:admin`。角色来自可信凭据文件，不来自表单；共享账户不能提供独立审批。
密钥与人员登录使用相同后端权限检查。

1. 申请人登录后进入访问申请，只读取有限的资源/入口目录，不读取策略、facts、其他
   人申请、管理审计或 Agent 凭据。
2. 明确填写来源 IP/CIDR，选择一个固定名称/UID 的资源及命名入口、60–86400 秒时长
   和原因。服务端规范化 IPv4/IPv6，并一次性确定绝对申请期限；提交不会开放访问。
3. 另一名获授权管理员刷新收件箱，审核保存的来源、目标/UID、命名入口与截止时间。
   批准只能取入口子集，期限只能保持或缩短；确认提示说明共享来源及发布不等于应用。
   管理员也不能自批。拒绝必须说明原因，目标移除/过期后仍可拒绝；允许拒绝自己的申请。
4. 同一事务提交独立限时 Grant、审批记录、追加式工作流事件及发布审计/修订。
   提交前完整编译并经过 Agent 预检，提交后才下发。数据库或下发失败继续采用既有
   停止运行/重新打开恢复语义，不把部分失败宣称成功。
5. 申请人可查看原申请及批准范围/期限、人员、原因、Grant UID/修订，以及当前期望
   Grant 的有效/撤销/过期/移除/未知状态。撤销独立 Grant 不会篡改原审批历史。
   这些不是独立执行证明；管理员在 Grant 页撤销贡献，在节点页检查真实报告、目标、
   活跃流及新鲜度。应用自身的认证仍然有效。

门户来源不自动等于服务实际看到的来源；代理、VPN、SNAT、路由及 IPv4/IPv6 选择可能
不同。浏览器转发头不证明映射。显式 CIDR 可能覆盖其他人员/设备，选择不证明所有权，
不创建隧道或应用凭据。首段允许申请目录中的资源，尚无逐资源申请资格策略或自动批准。

## 一致性与安全

相同业务接口分别位于 `/api/v1`（独立 Bearer）和 `/console/api/v1`（SCS Cookie、
准确 Origin/Host 与 Echo CSRF）：

| 操作 | 契约 |
|---|---|
| GET `/access-request-catalog` | 有限当前目录与强 ETag |
| POST `/access-requests` | 严格16KiB JSON，固定资源名称/UID、命名入口、来源、时长和原因，必需目录 If-Match |
| GET `/access-requests?after=0&limit=50` | 除 request:review 外仅本人；排他记录ID游标，每页最多100；可变的时间点观测，较早记录变化须重新刷新 |
| POST `/access-requests/{uid}/decision` | 待审批版本 CAS、动作/原因；批准另需当前发布 If-Match、入口子集及 RFC3339 绝对 expires_at |

申请时冻结网络形状（含目标地址）；重定位/移除/重建返回409，不能静默批准其他目标。
过期、延长或扩大的批准被拒绝，预检期间越过期限也不能提交。重复/并发决定只生成一份
贡献，不自动重试或续期。响应不明可能已提交，须刷新核对历史/人员/修订，再显式丢弃或
更新草稿基线；普通刷新不推进保留草稿或审核的 CAS 基线。

SQLite 发布 schema3→4 通过版本化事务新增申请、事件表及所有者索引，不迁移策略或
接管文件权威。Casbin 业务 schema1→2 一次性增加新默认权限：admin 可创建/读本人/
审核，requester 可创建/读本人，blocked 显式拒绝。保留全部既有/自定义规则；内置角色
对新操作已有规则时不替换。批准还需 publication:write。自定义角色须显式配置对应
操作。策略仍周期刷新，凭据每请求重读；人员审计 ID 不等于报文或业务请求身份。

## 验证与剩余范围

真实 HTTP/Casbin/SQLite 测试覆盖严格输入、本人隔离、deny 优先、自批拒绝、缩限/
绝对期限、目标重定位、迁移、事务回滚、并发决定及恢复。真实运行时测试验证批准的
IPv6 贡献经过 gRPC 精确下发，重启不改变权限/期限。Chromium 使用两个人员会话走真实
目录/表单/API、批准、拒绝、Grant/审计回读及撤销。最终准确源码、CI、截图和独立评审
以 PR32 与交付检查点为准，不从文档描述推断通过；保留全部旧浏览器/Nginx/Agent门禁。

不宣称 OIDC、账户CRUD、取消/通知、多级审批、逐资源资格、PostgreSQL/HA，或新增的
批准→特权Agent联合验收。当前仅单Controller/SQLite，申请/事件尚无保留/容量预算；
数据库备份须私密保存，其中包含敏感来源、范围、原因和人员。浏览器手动刷新并明确标记
年龄/失败，不是实时通知系统。继续路线图，不宣称整体发布完成。
