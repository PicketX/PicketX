# Controller Agent stream foundation

English (default) | [简体中文](AGENT_STREAM.zh-CN.md)

M2D1 provides a Controller-internal service, public typed protobuf and generated Go client. It is tested over actual protobuf/gRPC streams, including TCP loopback and verified server TLS. It does not yet wire the production Controller entry point or PicketXD provider. Run `go test -count=1 -race -v ./internal/agentsync ./pkg/agentsnapshot` to exercise the foundation. Kernel enforcement, provider-bound remote LKG, durable revisions, enrollment/administration and production configuration remain the next integration work.

## Controller assembly contract

Inside the Controller, construct `internal/agentsync.New(authority, Limits{...})` and register it with `agentv1.RegisterAgentSyncServer`. The generated public client is in `pkg/protocol/agent/v1alpha1`; the schema is `proto/picketx/agent/v1alpha1/sync.proto`. The package never opens a listener. The assembly owner must centrally start/stop the server, close the service and bound graceful shutdown (then use `grpc.Server.Stop` if peers remain).

Specify every positive limit; there are no silently unlimited defaults. Maximum credentials/active Agent scopes are each capped at 4096. Maximum snapshot frame size is at most 4 MiB. Establishment attempts have a service-local one-second window, counting authentication failures too; messages, including Hello, have independent per-stream one-second windows. Snapshot sends and the initial Hello have explicit timeouts. These counters are separate from ordinary HTTP, reset on process restart and are not cluster quotas. Establishment is bounded at RPC admission; the transport owner still controls pre-authentication connections, HTTP/2 concurrency and listener exposure.

Create the server with `grpc.MaxRecvMsgSize(agentsync.MaxWireBytes)` and `grpc.MaxSendMsgSize(agentsync.MaxWireBytes)`; use matching client message limits. Add standard `grpc.Creds(credentials.NewTLS(serverTLS))` for server TLS and `grpc.WithTransportCredentials(credentials.NewTLS(clientTLS))` on clients, with trusted roots and matching ServerName. Normal certificate verification is mandatory for TLS. Plaintext uses an explicit `insecure.NewCredentials()` client choice, has no confidentiality/server authentication and belongs on a deliberately controlled or tunneled hop. This increment requires neither mTLS nor an internal CA. Tests reject wrong certificate roots and wrong server names.

Credentials are a complete replacement set of `{ID, AgentRef, SHA256}` records. Generate raw Tokens from at least 32 cryptographically random bytes, encode without whitespace, provision securely and store only their SHA-256 in these service records. The wire accepts 32–256 printable ASCII bytes; length is not an entropy check. Never log raw Tokens or metadata. Each Token grants exactly its configured Agent scope; no request field chooses Agent identity. Use exactly one `authorization: Bearer <token>` metadata value. Rotation, deletion or rebind terminates old streams; one authenticated connection per Agent supersedes its predecessor. Invalid or oversized credential replacements are atomic no-ops. Revocation here is process-local; an authoritative store must propagate changes to every serving Controller before any fleet-wide revocation claim.

## Publication and reports

Call `Publish(candidate, revision)` with an immutable compiled configuration and a positive strictly increasing revision. Authority is fixed for the service. Replacement rechecks the shared planner's retained-identity/retarget constraints and prevents UID kind changes. Validation/size/revision failures leave the accepted publication intact. Revision persistence and restart rollback protection belong to the authoritative store that is not yet integrated. Publish does not constitute approval or enforcement.

Every currently enrolled Agent gets its own complete typed inventory. Newly enrolled scopes receive the latest publication, including explicit empty inventory for unknown/removed Agents. The payload retains target ownership, destinations, capabilities, Binding IDs and independent Grant/Deny IDs, future/expired/revoked contributions and absolute nanosecond deadlines. Empty targets mean complete withdrawal; disconnect never means implicit withdrawal. Intermediate revisions may coalesce for slow peers; reconnect receives the latest full state. Snapshot SHA-256 covers deterministic protobuf content with the digest field unset; it is an integrity/correlation value, not a signature or authentication mechanism. The Agent must validate domain semantics, local scope and provider identity before apply.

Hello version is 1; the `v1alpha1` schema is additive development surface without a stable compatibility promise. A report matches the last successfully sent revision/hash, has a valid RFC3339Nano observation timestamp and RECEIVED/APPLIED/FAILED phase. Obsolete/malformed reports terminate the stream; clients should report a current snapshot and tolerate replacement/reconnect. `Report(agent)` returns an independent copy, local server receive time and a Connected flag tied specifically to the reporting stream. An old report is visibly disconnected after a successor connects. An Agent timestamp is untrusted; do not infer freshness from it. APPLIED is an authenticated remote assertion, not independent proof of kernel state. Per-target apply/cleanup details and capability negotiation remain future protocol work; no usable management UI is implied.

## Reproducible generation

Use protoc 31.1, protoc-gen-go v1.36.11 and protoc-gen-go-grpc v1.6.1 on PATH, then run `scripts/generate-agent-protocol.sh`. The script rejects other tool versions. CI downloads the pinned upstream Linux protoc archive (SHA-256 `96553041f1a91ea0efee963cb16f462f5985b4d65365f3907414c360044d8065`), regenerates and rejects a changed binding. Runtime dependencies are pinned in go.mod/go.sum. Generation tools are build-time only and are not required by release binaries.

The tests include scoped completeness, independent deadlines, digest/copy integrity, revocation/rotation/rebinding, supersession/report races, explicit empty removal, atomic publication failures, shared retarget guards, bounded admission/messages, Hello/send timeout, slow-peer coalescing and shutdown. They do not establish remote Agent/kernel integration or fleet capacity.
