# Trusted HTTP source authorization

Architectural increment, approved for autonomous execution under the user's standing authorization. Baseline Core74575a4/Agent95a5f7f. Not product completion.

## Contract

Add `HTTPRoute` to the existing strict `picketx.io/v1alpha1` publication. Its spec has a pinned `resourceRef:{name,uid}`, one `endpointName` (existing TCP network Endpoint), exact canonical `host` authority, a nonempty explicit `methods` list (GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS), and a nonempty `paths` list of exact absolute canonical paths. No wildcard, prefix, query matching, identity claims, default methods or implicit HEAD. Method/path/host are conjunctive constraints; matching the route still requires an active existing source Grant and no active NetworkDeny for that entry. Paths reject percent escapes, backslashes, duplicate slash, dot segments, non-ASCII/control characters and fragments; URI query is ignored for matching and never recorded. Exact paths intentionally limit this alpha adapter; broader matching needs a later contract. Route names/UIDs have existing object identity rules. Route UID must not be retargeted while retained (remove/recreate with new UID for a new route target); methods/paths may narrow or expand only through authorized CAS publication. Existing Resource lifecycle checks remain.

Compile immutable HTTP intent alongside network intent, never into new network permissions. Unbound Resources may use HTTP-only enforcement; any selected network binding remains an independent gate, not claimed kernel application by an HTTP allow. Existing Agent wire format is unchanged and does not claim to enforce HTTPRoute. File/database policy remains one authority, no runtime permission layering.

## Trusted adapter

Opt-in dedicated listener, separate from console/admin: `authz.enabled`, `authz.network` tcp/unix, `authz.address`, `authz.credentials`. TCP must be an explicit IP loopback host:port (IPv4/IPv6); Unix socket must not exist and live in a private directory, mode0600; never remove/replace an existing object. Independent private JSON credential file `{callers:[{id,sha256,routes:[routeUID,...]}]}` read per request; max128 callers, max128 route UIDs each,1MiB file,32–256 printable ASCII Tokens, duplicate IDs/digests/routes and unknown fields rejected. Scope limits the trusted integration, does not grant source permission. No Agent/management/browser credential reuse or claimed user identities. Rotation/removal fails closed on next call; malformed credentials503. Readiness includes credential availability.

POST `/authz/v1/decisions` strict JSON `{route,source,host,method,uri}` max16KiB with dedicated Bearer. GET `/authz/v1/nginx` takes exactly one of each `X-PicketX-Route/Source/Host/Method/URI` header, set by an internal Nginx auth_request location; client-supplied headers never forwarded to this listener as authority. Generic JSON returns200 with allowed/reason/revision/grant IDs/deny IDs/nextChange and cacheTTL0. Nginx returns204 only for allow,403 for policy deny,401 for invalid credential,503 for unavailable,400 for malformed context; no positive caching. No cookies/forwarded-header IP extraction; time is server-side UTC, source is canonical IP only, zones/mapped IPv6 rejected. Unknown or out-of-scope route403 without cross-scope details. All results no-store. Echo adapters stay thin; core remains framework/ORM independent.

Every valid scoped decision is persisted before return with caller ID, route UID, source IP, desired revision, allow/reason, contributing IDs and evaluation instant. Never store URI/query/Host/method/body/Token. Versioned SQLite schema3 migration; audit persistence failure503, no returned allow. Bounded audit GET `/api/v1/http-decisions` and cookie counterpart require existing audit RBAC, cursor semantics match publication audit. Single process/SQLite throughput is unmeasured, not HA. No stream/WebSocket termination promise; every new request is evaluated even on an existing connection.

## Delivery evidence and limits

TDD for route/Grant/deny/independent deadline/unknown and canonicalization boundaries; persistence/reopen/audit failure; actual loopback TCP and Unix decisions, credential revocation and listener shutdown. Actual Linux Nginx binary (auth_request enabled) forwards only allowed requests to a real application; same keepalive connection switches denied Host/method/path, source spoof headers cannot widen access, expired/revoked/denied contributions remain denied. Extend actual Chromium console flow to publish HTTPRoute and observe real Nginx application reachability/revocation, while retaining existing console scenarios. Missing Nginx setup is a failure, never skip. No new Agent/kernel behavior, production HTTPS, identity/OIDC, structured workflow UI, performance or full product completion claim.

Alternatives considered: add independent HTTP grant storage (rejected: duplicates lifetimes/authority); project HTTP rules into Agent now (deferred: larger transport/backend contract); initial exact-route source gate (chosen: actual HTTP enforcement with existing core semantics and honest limits).
