## 1. 目标与已同意方向

下一项交付是可复用的 Go 授权引擎：在明确时间，解释某个 IP/CIDR 来源可以访问哪些命名服务入口。Controller 工作流和官方 Agent 复用其语义。来源不等同于申请人、门户 Session、角色、设备或应用身份。

首个产品流程仍是 Gitea：HTTPS 和 SSH 独立入口、浏览器申请/审批、限定来源的访问、可见的应用状态与过期。本增量证明该流程需要的共享逻辑权限语义，不表示浏览器到内核的流程已经完成。

已同意：主机地址和 CIDR 匹配授权取并集、拒绝优先、Grant 独立期限、IPv4/IPv6 同等支持、先实现固定绝对期限、整项资源与命名/标签入口选择、不强制要求来源 Session。本设计补充一个小范围内部 Go 契约，不发布仍未确定的 YAML/REST/protobuf 模型。

## 2. 增量边界与方案

| 方案 | 影响 |
| --- | --- |
| **先实现共享 Core（推荐）** | 在持久化和通信之前用确定性测试证明领域行为，后续各层使用同一引擎 |
| 先实现审批/API/存储 | 较早出现可见流程，但在公共契约形成前，业务和 Agent 可能重复实现网络语义 |
| 先完成整个清单/Binding/运行时契约 | 一次覆盖更多集成，但需要先确定身份、生命周期、部署位置和通信等未决项 |

采用第一种。在现有模块 `github.com/PicketX/PicketX` 的 `pkg/core` 增加小型公开 Go 包。Go 包名和类型初期属于可演进的实现 API，不是稳定的线协议。包只使用标准库，不导入 HTTP/ORM/Casbin/Linux，不管理 goroutine、数据库、socket 或系统时钟服务。

首批包括来源规范化、已定标签选择器、入口选择、显式期限/撤销状态、经过校验的网络 Grant 贡献，以及确定性决策和解释。资源选择先支持显式 Resource 引用。广泛 Resource 选择器与入口名称的组合、全局 ALL 编码、Agent 部署和清单解码另行设计。

引擎回答**逻辑命名入口查询**，不负责把报文目的地映射到逻辑 Resource、计算主机/网关范围、编译 nftables 或授权任意流量。后续可信规划器必须解析实际目的地址/协议/端口和 Binding 范围。逻辑允许不等于报文允许，也不代表已执行成功。

## 3. 规范化输入模型

下列名称说明 Go 领域对象的职责，不是最终外部字段名。

| 输入 | 必需含义 |
| --- | --- |
| Resource 目录 | 显式命名资源、资源内唯一命名入口、独立的资源/入口标签和支持的入口类型 |
| Network Grant | 非空且唯一的贡献 ID、一个规范来源前缀、非空作用域、共享期限和显式撤销状态 |
| Scope | 已存在的 Resource 引用、恰好一种入口选择模式和支持的动作 |
| 入口选择 | 整项资源、非空名称清单或非空标签选择器；构造函数区分省略与非法空值 |
| 网络限制 | 独立且唯一标识的拒绝贡献，包含来源、作用域和期限；不等同于申请资格策略 |
| 查询 | 有效来源地址、已存在的资源和入口、支持的动作、可信调用方提供的明确且非零评估时间 |

初始入口类型是 `network`，动作为 `connect`。省略类型/动作使用这两个已定默认值；显式空动作清单非法。不支持的类型、主体、动作、条件或续期要求必须报错，不能被丢弃或降级。

贡献 ID 使用不透明内部字符串，用于去重和解释；不确定持久化 UID 格式、重命名/删除重建规则或 protobuf 表示。Grant ID 和拒绝 ID 属于独立贡献类别，同一类别内 ID 重复使整个候选失败。

校验全部输入，包括已撤销、已过期和当前不匹配的贡献。未知资源引用和缺失命名入口使校验失败。非法候选不产生可用编译引擎或部分新决策状态。资源选择器没有匹配结果不能变成整项资源授权；广泛资源选择器不属于本增量接受的输入。

### 来源地址

普通 IPv4/IPv6 地址规范为 /32 或 /128。明确输入的 CIDR 规范为掩码前缀；调用方授权观测到的主机时必须走主机地址路径，不能自行构造更宽 CIDR。规范来源契约拒绝非法值、域名、带 zone 的 IPv6 和 IPv4 映射 IPv6。编译后的前缀必须有效且规范。

IPv4 前缀只匹配 IPv4 来源，IPv6 前缀只匹配 IPv6 来源。考虑全部匹配前缀，不只取最长匹配。来源和目的地址职责分离；本增量不将来源前缀解释为目的范围。

### 入口与标签选择

整项资源包括当前全部入口及目录未来增加的入口；命名选择限于明确名称；标签选择根据当前目录匹配。空名称清单、空选择器和混合模式非法。资源标签不自动继承到入口。

实现已定 `matchLabels` 等值和 `In`、`NotIn`、`Exists`、`DoesNotExist`：条件 AND，`In` 值为候选，缺失键匹配 `NotIn`，存在性操作符不得提供值。`NotIn` 是选择过滤，不能取消另一份 Grant 的允许。Core 构造输入保留是否提供值，因此存在性操作符显式提供空清单也会被拒绝。

## 4. 期限与撤销

规范化期限有两种显式模式：有期限、永久。零值/默认模式非法。有期限贡献必须有非零绝对结束时间；永久贡献不能同时提供结束时间。可选非零开始时间限制激活。有期限结束时间必须严格晚于已提供的开始时间。

有效区间为半开区间：开始时刻包含，结束时刻不包含；达到期限即不再贡献权限。规范到 UTC，不改变时间含义。引擎不读取 `time.Now`，评估时间由调用方提供。重新编译或重启不能将绝对结束时间改成“当前时间＋原始时长”。

撤销只移除该贡献在新决策中的作用；永久贡献撤销后也无效。不同来源、作用域和期限仍使用不同 Grant。已有连接的平滑/严格处理归执行层；逻辑决策不承诺发送 TCP reset 或删除 conntrack。

这个内部期限表示不确定外部永久授权语法、条件语言或可选 Lease 模型。活动续期和来源 Session 失效不属于本增量。

## 5. 决策、解释和状态所有权

将校验通过的目录/贡献编译为不可变快照，复制调用方拥有的 map 和 slice。调用方后续修改不能影响已安装引擎。替换快照先编译新引擎，再由调用方切换。并发决策只读，不需要全局注册表或决策缓存。

对时间 `t` 的查询：

1. 解析已存在的逻辑资源/入口和支持的动作。
2. 收集来源和作用域匹配、未撤销且当前有效的全部 Grant。
3. 收集当前有效且匹配的全部显式拒绝贡献。
4. 拒绝优先；否则有任意匹配 Grant 即允许；没有匹配 Grant 即拒绝。

解释返回排序去重的 Grant ID、拒绝 ID、匹配 Grant 的来源/期限和原因：`allowed`、`no-active-grant` 或 `explicit-deny`。保留各贡献的绝对期限，不能把 HTTPS/SSH 合并成一份来源全权限，也不能统一延长到最晚期限。

存在未来相关激活/过期时，返回其中最早时刻 `nextChange`，供消费方重新评估。它**不是**新授权期限、续期、Lease 或生效延迟承诺。一份贡献过期但另一份仍允许时，重新评估仍须保留有效授权；贡献解释变化也可以触发重新评估。

非法查询返回错误，不能伪造允许或任意整项资源匹配。解释包含授权来源记录，不证明谁产生了报文。决策不包含 Agent 的期望/已应用状态。

## 6. 确定性与契约验证

使用显式时钟和小型字面量夹具，不要求 Linux 权限。输出排序，输入顺序/map 遍历不能改变解释。等价规范输入产生等价决策，无论将来由 Controller 或 Static 提供。本增量不实现解码器或 provider。

| 用例 | 必需结果 |
| --- | --- |
| IPv4/IPv6 主机规范化与显式 CIDR | 正确规范前缀，不擅自扩大观测主机范围 |
| 非法/映射/带 zone 地址或非法类型化前缀 | 校验错误 |
| 精确主机与更宽前缀 Grant | 保留两个贡献；撤销其中之一仍保留另一份匹配授权 |
| HTTPS 至 10:00，SSH 至 12:00 | 10:00 时 HTTPS 拒绝、SSH 允许 |
| 另一份 HTTPS Grant 至 11:00 | 第一份过期后 HTTPS 仍允许，已过期 ID 不再贡献 |
| 开始/结束边界、永久/撤销状态 | 开始包含、结束排除，零值不意外变成永久 |
| 匹配且有效的拒绝 | 优先于所有允许，非有效拒绝不影响结果 |
| 缺失标签匹配 `NotIn`，再加 `Exists` | 前者匹配、后者不匹配，不能当作显式拒绝 |
| 增加目录入口后的整项/命名/标签选择 | 整项扩展、命名固定、标签随匹配变化 |
| 重复贡献/目录标识及缺失命名入口 | 整体拒绝，不产生被扩大的部分结果 |
| 省略 network/connect 与明确默认值 | 相同规范意图和决策 |
| 空选择/动作及不支持的条件/类型/动作 | 拒绝，不能当作省略/全部 |
| 重排等价快照、编译后修改原始数据 | 解释稳定，已安装引擎不变 |
| 未来相关开始/过期时刻 | 正确最早 `nextChange`，不改变 Grant 期限 |
| 未知资源/入口和零评估时间 | 查询错误 |
| Gitea HTTPS/SSH 与来源重叠授权 | 联合验证独立入口、期限、撤销和解释 |

测试使用人工推导的 ID、布尔值和时间。可增加小范围穷举/参考检查来验证聚合行为，但不能复制实现逻辑作为期望。本阶段不是十万来源基准测试，也不宣称性能容量。

## 8. M1 后续顺序

共享逻辑 Core 通过评审和测试后，定义规范物理入口/Binding 规划器，以及 Core 到 M0 的契约桥接。该阶段必须明确主机/网关范围、目的匹配、所有权冲突和目录编辑/生命周期规则，不能从逻辑名称推断。

随后实现首个持久化/审批切片，包含版本化业务迁移、可信操作者/来源处理和可靠发布；再逐步接入 Agent 通信、应用状态以及 Gitea 门户/CLI 流程。Casbin 用于已选管理 RBAC 边界，不替代网络 Grant 并集。OIDC/SCS、UI、gRPC 和本地 AuthZ 按各自聚焦设计实现。

不以通用工作流引擎、租户平台、任意 ABAC 语言或事件流框架作为本增量前置条件。
