# M2A: Static network configuration entry point

> English (default) | [简体中文](2026-10-15-static-configuration-design.zh-CN.md)

- Status: Implemented, locally verified and independently reviewed; remote acceptance is recorded in the PR.
- Scope: a reusable strict decoder/compiler and a runnable configuration-check CLI. Agent installation, directory watching/LKG, transport, kernel application, L7 and administration follow separately.
- Baseline: PRODUCT_DESIGN, ARCHITECTURE and CONFIGURATION_MODEL. No GPL Agent source enters this repository.

## Intent and decisions

Make a complete network policy writable and checkable without constructing Go structs. Reuse Core and networkplan; accepted configuration is desired intent, never proof of application. A single multi-document YAML file is a complete candidate. Its publisher must atomically replace the file; do not infer a multi-file transaction from a debounce timer. No directory watcher is included.

Use `picketx.io/v1alpha1` objects: Resource, Grant, NetworkDeny and EnforcementBinding. NetworkDeny is specifically a runtime source restriction, not request eligibility or approval policy. Unknown versions/kinds/fields and user-supplied status fail. Reject explicit null, duplicate keys, non-string keys, aliases/anchors, merges and custom tags. Limit input to 4 MiB, 4096 objects and 64 nested nodes. Empty input fails; a single `Configuration` object with `spec: {empty: true}` is the explicit complete withdrawal form and cannot coexist with other objects.

Metadata has nonempty name, explicit opaque uid, optional string labels/annotations. Names are unique within kind; UIDs are unique across the candidate. UIDs use 1–128 ASCII letters/digits/dot/underscore/hyphen. Resource references require both name and uid and are resolved before compilation. This pins named Grants across resource delete/recreate; a reused display name with a fresh UID does not inherit an unchanged Grant reference. Core/networkplan resource identities use Resource UIDs; Grant/Deny/Binding contribution identities use their UIDs. Embedded Endpoint names remain stable entry keys. Changing physical meaning with retained contribution IDs is rejected by networkplan.Replace. Rename retains UID and requires updated reference names. Cross-generation UID kind changes fail; persistent tombstones and authorization of fresh issuance remain the publisher's responsibility, not inferred approval.

Resource endpoints require name and network protocol (TCP/UDP) and port (1–65535); type defaults to network. Optional addresses are a nonempty IP/CIDR union. Bindings require resource selections, Agent selections and explicit enforcement profile/class/stage/destination boundary/handling. Agents and resolved execution contexts come only from separately supplied operator/runtime facts, not policy objects. These facts still require live adapter validation before enforcement. Broad Resource selectors remain unsupported, matching the current planner. Endpoint names/label selectors and Agent names/label selectors reuse existing semantics; omitted Endpoint restrictions mean whole Resource, while null/empty restrictions fail.

Grants/NetworkDenies require one `subject: {type: source, cidr: ...}`, nonempty named-resource scopes, and validity. Validity requires `mode: bounded` with absolute RFC3339 expiresAt or `mode: permanent` without expiresAt; optional absolute notBefore; optional revoked defaults false. Omitted actions default connect; explicit empty actions fail. Unknown conditions/renewal requirements fail rather than disappear. No requester or portal identity is inferred from source.

The decoder owns its input. Compilation validates the entire bundle, including unmatched, revoked and expired objects. Replace uses the previous compiled Candidate and networkplan.Replace; a failure returns no replacement or withdrawal. Expose immutable Plan, independent Input copies, object identities and SHA-256 of normalized object JSON. Object order and explicit network/connect defaults do not affect this hash; spelling/prefix/selector list normalization beyond those defaults is not promised. Deadlines remain absolute on every replay. Empty configuration retains trusted runtime inventory but withdraws all protection; it is distinct from keeping Bindings with no Grants.

`picketx config check --file policy.yaml --facts facts.json [--at RFC3339]` uses Cobra v1.10.2, outputs JSON to stdout and diagnostics to stderr, nonzero on error. Facts require exact struct-field spellings (including Unicode), reject duplicate/null keys, and preserve case-sensitive label maps. They are a strict JSON document containing authorityID, agents and contexts using the existing evolving Go planner representation; they are a diagnostic input, not a stable enrollment/runtime settings API. No environment/file settings precedence or Koanf loader is introduced. Report `state: validated`, `enforcementConfirmed: false`, hash, identities and explicit-time per-Agent projections. Never label validation applied. Bound facts to 4 MiB and reject unknown/trailing JSON. No privileged operation or network listener.

Choose stable maintained-path YAML v3 v3.0.5 for this narrow node parser rather than v4 release candidates; pin Cobra v1.10.2 as already agreed. Record dependency licenses. Keep the policy DTOs separate from Core, HTTP, database and runtime facts. This alpha schema is additive work, not an assertion that previously open wire contracts were already approved or implemented.

## Acceptance

Test literal dual-stack Gitea HTTPS/SSH, independent lifetimes, deny precedence, future boundaries, all selection-presence cases, strict unknown/duplicate fields, invalid types/limits, pinned references, same-name recreation, UID uniqueness/kind reuse, full-candidate failure, retargeting rejection, explicit empty withdrawal, owned input/output, order/default hashing and absolute deadline replay. CLI tests execute real decoding/planning with temporary files and assert errors never emit successful JSON. Verify Go test/race/vet/build and a static Linux binary, run examples at fixed times, review the complete branch, then publish and inspect CI.
