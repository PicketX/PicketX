## 1. 目标与已选择的方式

用户已同意先做独立物理规划层，再接 M0。规划层将逻辑 Resource/Endpoint 授权和明确的部署 Binding，转换为可重建的每 Agent 保护与权限意图。验收重点是：具有独立期限的来源权限映射到正确的物理流量范围，不静默扩大范围，不丢失来源记录。

| 方式 | 取舍 |
| --- | --- |
| **独立规划层，再接 M0（已选择）** | 先验证共享物理意图，再引入后端和运行时行为 |
| 固定 Gitea-to-M0 场景后再通用化 | 较早获得单场景流量证据，随后抽取选择和所有权语义 |
| 规划层与生产 Agent 同步开发 | 较早集成生命周期和应用，但验证及失败边界显著扩大 |

M1.2 在 `pkg/networkplan` 交付仅依赖标准库的规范化规划层，并由 `pkg/core` 提供范围有限、具有独立数据所有权的入口/贡献视图。M1.3 再通过单独的聚焦设计，在 PicketXD 实现 M0 契约桥接。此拆分保持已同意顺序；M1.2 不把 M0 私有 fixture 导入或升级为公开契约。

不添加产品依赖、HTTP/数据库/Casbin/Linux 导入、goroutine、系统时间、传输、Manifest 解码、持久化生命周期服务或 UI。GPL Agent 实现不得复制到 Apache 仓库。下文 Go 名称描述职责，具体签名由实施计划确定；这不是 YAML/REST/protobuf Schema。

## 2. 规范化输入与 Core 复用

| 输入 | 含义与校验 |
| --- | --- |
| 逻辑快照 | 现有 Core Resource、Grant 和 Deny；来源、选择与期限以现有语义为准 |
| 物理定义 | 按精确 Resource/Endpoint 引用，为每个逻辑入口提供且只提供一个网络定义；无孤立或重复定义 |
| Agent 清单 | 可信且唯一的 Agent 引用、独立 Agent 标签、声明的能力描述；离线 Agent 仍在清单中 |
| 实施上下文 | 可信的每 Agent 网络空间身份、流量类别、观察阶段、明确目的边界；不从名称或标签推断 |
| Binding | 唯一非空 Binding ID、非空 Resource 与 Agent 选择列表、每个选中 Agent 的明确上下文引用，以及兼容的连接处理要求 |
| 前一计划 | 来自同一权威来源的可信已接受计划，用于替换校验和撤回解释；不是额外授权来源 |

第一版物理定义要求明确 TCP 或 UDP，以及 1–65535 的单个目的端口。协议没有默认值。本增量不支持端口范围、NAT64、隐式端口映射、DNS 目的地址或 DNAT 后策略匹配；传入这些要求必须失败，不能简化。M0 能测试端口范围，不等于产品已经确定对应字段。

目的前缀采用与来源相同的 IPv4/IPv6 规范规则，但角色独立。普通地址规范化为 /32 或 /128；显式 CIDR 在拒绝非法、mapped、zoned 地址后掩码化。非空目的列表取并集；nil 表示省略；显式非 nil 空列表非法。每个地址族的并集通过移除被包含的重复项、合并完整兄弟前缀规范化，确保等价集合比较相同，不展开单个地址。外部 null/未知字段由后续解码器严格处理，Adapter 不能将其变为合法省略。

Binding 的 Resource 项先使用精确引用，复用 `core.EndpointSelection`：省略选择整个 Resource，或指定非空名称/标签限制；广泛 Resource selector 在单独设计前拒绝。Agent 项只能是一个已知引用或非空 Core 标签选择器，结果并集去重。选中入口应用到每个选中 Agent，不能按位置配对。每个 Binding 提供一个非空上下文引用，在每个选中 Agent 自己的可信上下文目录内解析；上下文 key 按 Agent 隔离，选中目标缺少上下文即失败。Agent selector 无匹配时产生空目标及诊断，不能变成 ALL；明确引用不存在时报错。Resource、Endpoint、Agent 标签不继承。

Core 仍是 Grant/deny 校验、逻辑成员关系与期限的唯一权威。在已编译 Core 增加确定性且返回独立副本的入口/贡献视图，包含未生效、未来生效和已撤销贡献，再由规划层消费。不暴露 Core 内部可变 map，不通过遍历原始 Grant scopes 重写权限计算，也不能从单点查询推断整个前缀的权限。Binding 入口选择复用现有 Core 原语。保留 M1.1 全部行为和测试。

## 3. 实施范围与地址省略

每个选中的 Agent/Binding 组合必须解析为一个明确实施上下文，包含：

- Agent 身份和可信运行时解析器提供的不透明网络空间身份；用户随意提供的不同字符串不能证明隔离。
- 明确流量类别：主机本地入站、发布服务入站或转发。主机部署仍是产品默认体验；进入规范层的上下文必须明确且已解析。容器发布流量不自动等于主机本地流量。
- 本增量采用原始目的地址观察契约，包含该实施点实际观察的来源。具体 hook/网卡谓词由 Adapter 负责。
- 非空规范目的边界并集，由明确配置/运行时上下文解析。仅在显式表达且能落实流量类别约束时，才允许覆盖整个地址族的边界；不能由省略生成。
- 所需能力与连接处理信息。未知类别/阶段、选中目标缺少能力描述或已知不支持的要求使候选失败，包括不支持的地址族、TCP/UDP 及 graceful/strict 处理要求。离线目标不消失；过时的能力声明不证明当前已实施，Adapter 应用前仍须核对实际能力。

每个选中入口的物理目的集合，是入口显式 addresses 与上下文边界的交集。入口省略地址时使用上下文边界，保留其 IPv4/IPv6 限制。选中入口的交集为空时，返回包含 Agent/Binding/入口的错误，不能静默消失。IPv4-only 地址列表不会获得 IPv6 覆盖。

目的前缀本身不能证明主机/转发隔离。计划必须一直保留流量类别和上下文要求；后端即使能表示目的地址，无法落实类别约束时也必须拒绝投影。规划层不探测网卡、不打开 namespace、不创建路由、不发现容器拓扑。

这是实际 M0 代码要求的边界：它在 PREROUTING、优先级 -110 使用明确目的地址 fixture；NAT 测试匹配原始 VIP/端口，并单独核对转换后的 reply tuple。这不能证明生产主机/容器实施范围。将省略地址直接转换为该链上的 0.0.0.0/0 和 ::/0，会丢失 Binding 边界。

## 4. 计划内容、时间与所有权

编译产生完整校验的不可变计划。非法候选不返回部分计划；非法替换不修改已安装计划。复制调用方集合，结果集合也独立拥有数据。等价输入的顺序/默认值不能改变排序后的投影和诊断。

每个 Agent 的投影包含：

1. 受保护逻辑入口及物理目的地址/协议/端口匹配，连同实施上下文要求。
2. 全部贡献 Binding ID。同入口、同上下文、同物理匹配的相同贡献可以共享保护表示，但不能丢失所有权。
3. 相关 Grant/Deny 来源记录、规范来源、明确期限与撤销状态。未来起点保留供后续重算；跨地址族的来源/目的组合不能成为权限。Grant/Deny ID 域保持 Core 的独立语义，即使字符串相同也不混淆。
4. 完整期望自有目标清单，以及相对前一计划的确定性差异，包括应撤回目标。空投影表示明确的自有期望空状态，不能视为失败或清空无关对象的请求。

以明确时间生成当前有效 allow/deny 成员及最近相关未来起点/终点。只要仍有 Binding 贡献，最后一个 Grant 到期或删除后入口仍受保护。删除一个 Binding 保留其他 Binding；删除最后一个 Binding 请求撤回对应自有保护。撤回请求不代表清理已经成功。未被任何 Binding 覆盖的入口属于该投影未管理范围；逻辑允许或空投影不能声称拥有无关主机流量的权限。

每条贡献保留绝对期限，不能换成来源或 Resource 的最晚期限。来源前缀重叠取权限并集，有效 deny 优先，撤销一条仍保留其他允许。已撤销、已过期及当前未用输入仍完整校验。调度信息包含未来 deny 生效和 deny 到期；重载、重启及非法替换不能续期。

领域意图按保护入口、上下文与物理匹配分组，并保留贡献成员关系。这不规定每 Grant 一条内核规则，也不确定最终 nftables set 布局。后端后续聚合时不能改变地址、来源记录或独立期限的效果；本设计不承诺容量或规则数量上限。

graceful 与 strict 撤回是不同的明确要求。记录所需行为，拒绝不兼容共享；Core/规划层不执行 conntrack 删除、TCP reset 或连接观察。应用确认和精确 strict 撤销仍由 Agent 负责。

## 5. 物理冲突

在解析后检查物理声明，不受当前是否存在 Grant、过期、撤销或有效来源的影响。逻辑名称不同，不会让同一流量获得独立实施身份。

第一版在相同可信 Agent/网络空间内，比较原始目的地址、协议、端口及重叠目的前缀。不同上下文 ID 或标签不能证明不相交。不同 Agent 是独立目标，不承诺跨 Agent 事务。

- 同一逻辑入口、相同规范上下文、流量匹配和连接行为，可以合并 Binding 来源记录；比较前对等价地址并集规范化。
- 不同逻辑入口的物理范围重叠时，整份候选失败；同一 Resource 下两个 Endpoint 也适用。不能隐式引入共享保护别名模型。
- 同一入口在不兼容上下文或行为下的范围重叠也失败。第一版可保守拒绝无法证明不相交的上下文，但必须明确报告限制，不能承诺独立隔离。
- 不相交目的范围、不同协议或端口可以共存。前缀包含也算重叠，不能只比较前缀字符串是否相等。

这支持不同 Agent 上的普通主机/网关部署，并阻止单个目标上的意外 L4 别名。更宽松的共享需要明确契约。

## 6. 替换与生命周期保护

第一版采用完整权威替换，不使用命令式 grant/revoke。为替换检查保留完整规范入口定义和已解析贡献成员，包括未绑定/未生效入口，不能只保留当前有效投影。前一计划不可变并绑定 provider 身份，不合并 Controller 和 Static 状态。协调现有安装时，运行时必须提供/恢复对应历史清单。可信首次初始化可以没有前一计划，但不因此接管未知防火墙状态。

本增量采用以下规则：

- 添加入口、改变标签，保留已同意的 whole-Resource/标签动态选择语义；名称选择仍仅覆盖指定入口。管理授权仍在规划层外完成。
- 改变已有入口的目的并集、协议或端口属于目标重定向。若旧 Grant 或 Deny ID 在候选中仍解析到该入口，默认拒绝替换。第一版要求显式以新贡献 ID 重新签发并保留绝对期限；不自动迁移授权或重置期限。即使当前某个 Binding 边界隐藏了变化区域，规范定义的变化也适用。
- 上下文身份不可变：复用上下文 ID 时改变网络空间、流量类别、观察阶段、目的边界或连接行为，候选失败。新上下文/部署需独立校验，包括冲突与清理清单。
- 缺失名称引用失败。入口删除/重命名按完整候选中的删除/新增处理；名称 Grant 必须删除，或显式针对现存名称重新签发。whole/标签选择仍保留刻意的动态语义。
- 持久化 UID 格式、跨重启 tombstone、已删除名称/ID 的复用不属于本规范化规划层。不声称单个全新快照能检测历史删除/重建；生产发布/恢复必须先明确持久身份，再开放这些生命周期操作。

这些是第一版保守的部署规则，不替代申请审批、管理 RBAC 或通用迁移引擎。失败时指出具体目标及冲突/保留 ID；保持前一有效计划，其原有期限继续流逝。被拒候选不能触发部分清理。

## 7. M0 桥接边界与后续证据

桥接是 PicketXD 的下一增量，依赖有版本的 PicketX Core/规划层。Apache 组件不能依赖 GPL Agent 实现；当前 `internal/validation/fixture` 保持私有。

桥接应用前，应声明具体 fixture 拓扑、原始 tuple 观察契约、可实施的流量约束及连接处理能力。薄转换器只能接受能够在一次性拓扑中完整证明上下文的投影；fixture 未证明的主机/发布服务或一般网关要求必须拒绝，不能丢弃上下文字段后声称兼容。

在明确时间，将当前有效贡献和绝对期限转换为 M0 私有 allow/deny/protected fixture。未来生效需要运行时实际重算机制；原生到期不会自动激活未来规则，转换器不是自主调度器。M0 的零到期时间只代表 fixture 永久成员，只能由明确 permanent 贡献生成，不能由省略/非法期限生成。

M0 当前拒绝空 Protected 列表。因此，转换器不能把自有期望空状态静默变为非法 Apply 调用、无操作成功、全局 flush 或无边界通配。桥接声称支持这类生命周期前，必须单独实现自有对象清理及确认。

真实内核验收必须证明生成的物理意图、逻辑 Core 决策和实际新连接一致，包括重叠、HTTPS/SSH 独立期限、deny、撤销和重启。strict 撤销先应用并确认新策略，再仅删除撤回的自有 conntrack 流，并确认剩余目标；保留其他 Grant、mark 和无关流量，禁止全局 conntrack flush。按实际观察来源匹配，NAT original/reply tuple 保留现有精确检查。决策与数据包只在声明的自有保护范围内比较；无关流量作为明确的未管理对照。

M1.2 纯测试不能证明数据包兼容。M1.3 必须记录真实特权 Linux/工具链/依赖版本和数据包结果；跳过或 mock 内核测试不算成功。生产主机本地、容器发布和一般网关/NAT 覆盖，需要各自的实际路径和证据。

## 8. 验收与上下文地图

下列是拟定的 M1.2 验收要求，不是已实现测试结果：

| 场景 | 必须结果 |
| --- | --- |
| 明确 TCP/UDP 和端口；缺协议/零端口/端口范围要求 | 合法单端口意图，或明确不支持/非法错误 |
| 缺失/重复/孤立物理定义、非法未生效贡献 | 整份候选失败，不返回部分计划 |
| 省略地址与非 nil 空值/mapped/zoned/DNS 输入 | 使用受限边界，或校验错误 |
| 边界 192.0.2.0/24，入口 192.0.2.128/25 | 恰为 /25，不扩大目的范围 |
| 双栈边界中的 IPv4-only 列表 | 仅保护 IPv4，不虚构 IPv6 或来源地址族转换 |
| 已选入口交集为空或缺上下文 | 诊断错误，不能无限制或静默省略保护 |
| 多入口/多 Agent Binding，Agent 重复匹配 | 笛卡尔积、去重、保留全部 Binding 来源 |
| Agent selector 无匹配，或引用的 Agent 离线 | 空目标诊断，或保留期望目标 |
| 逻辑允许的入口没有 Binding | 无物理目标，不声称已实施；无关流量仍未管理 |
| 主机来源和宽 CIDR；HTTPS/SSH 独立期限 | 保留全部贡献，独立到期，deny 优先 |
| 未来 allow/deny 起点、deny 到期、撤销永久贡献 | 正确当前成员和重算时间，不复活权限 |
| 不同逻辑入口使用相同 tuple，或前缀相交 | 没有有效 Grant 也冲突，名称不能形成隔离 |
| 同入口/上下文被两个 Binding 引用，删除一个 | 共享保护仍保留另一 Binding 来源 |
| 最后一条 Grant 到期、最后一个 Binding 删除 | 保留保护，或产生明确自有撤回清单 |
| 保留旧 ID 时重定向目的/端口，或修改上下文 ID 含义 | 拒绝替换，旧计划与期限不变 |
| 重排、修改输入/结果、并发读取计划 | 确定性、独立所有权、只读结果 |
| 等价 Controller/static 风格规范输入 | 投影相同，不声称已有 provider/decoder |

拟定职责地图：

| 范围 | 拟定文件 | 职责 |
| --- | --- | --- |
| Core 解析后的入口视图 | `pkg/core/network.go`、`network_types.go`、聚焦测试 | 单一权威的已解析贡献视图，保留 M1.1 决策 |
| 物理规范化与上下文 | `pkg/networkplan/types.go`、`network.go`、`context.go`、测试 | 规范目的地址、明确协议/端口、可信实施边界 |
| 部署与冲突校验 | `pkg/networkplan/binding.go`、`conflict.go`、测试 | 笛卡尔积解析、复用选择、物理重叠与来源记录 |
| 不可变计划与替换 | `pkg/networkplan/plan.go`、`transition.go`、测试 | 每 Agent 意图、明确时间成员、重定向保护与撤回清单 |
| 契约与说明 | `pkg/networkplan/conformance_test.go`、`example_test.go`、`doc.go`、双语 README | 固定 Gitea 断言、公开用法和真实后续集成范围 |

实施计划将基于地图确定具体类型/函数签名和 TDD 任务。现有 Go CI 已对 `pkg` 做格式检查并执行 vet/race/build；新增代码不改变 go.mod/go.sum。本设计 PR 仅含文档，不创建上述包、桥接、迁移服务或生产 Agent。
