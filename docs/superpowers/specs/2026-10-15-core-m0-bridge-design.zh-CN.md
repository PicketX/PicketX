## 1. 目标与已选择的边界

已同意的下一增量将共享逻辑/物理意图接入现有真实内核验证设施。验收要求：在明确、自有的夹具范围内，Core 决策、生成的保护/来源成员与实际新连接一致，覆盖替换、独立期限及精确范围 strict 撤销。交付仍是验证设施，不是生产 Agent，也不是浏览器到内核的完整产品工作流。

| 方式 | 结果与取舍 |
| --- | --- |
| **隔离契约桥接（已选择）** | 复用 M0 命名空间/后端，以明确夹具契约先验证转换和生命周期，再引入生产协调 |
| 在测试体内嵌入 Gitea 专用转换 | 首次差异较小，但多个生命周期测试会重复上下文/来源记录/历史处理 |
| 直接接生产 Agent | 在证明共享意图到内核的边界前，就需要加载、持久恢复、传输与服务生命周期 |

实现位于 GPL-3.0-or-later 的 PicketXD 仓库 `internal/validation`。依赖 Apache PicketX 模块的不可变版本 `e39f96e2787154a8af8e7d996b2f65aa10b6c3eb`；实施时用 Go 工具解析并记录对应伪版本及校验和。不提交浮动分支依赖或机器本地 replace。保持 Go 1.27.0 和现有固定 Netlink 模块版本，除非实现证明存在具体必要变更。仅导入 `pkg/core` 和 `pkg/networkplan`，Agent 二进制的包依赖图不能因此带入 Controller/Web 框架。模块图仍可能记录共享模块已有的 require，须区分它与实际链接的包导入。

不向 PicketX 复制 GPL 代码，不将 `internal/validation/fixture` 升级为公开 Schema，不添加 Controller 客户端/static Manifest 解码，也不实现生产就绪状态、持久审批关联、持久 UID、通用调度服务、Session、mTLS 或 UI。M1.2 混合 Agent selector 诊断 Minor 继续记录在 PR #7；桥接使用明确夹具 Agent 引用，不顺带扩大范围修复该问题。

## 2. 绑定实际拓扑的契约

当前 `kerneltest.Topology` 分为 Client、Enforcement、Server 三个命名空间。保护目的和 NAT VIP 均分配给 Server，而非 Enforcement；Enforcement 开启 IPv4/IPv6 转发。nftables 入站链位于 PREROUTING priority -110，夹具 DNAT 链位于其后的目的 NAT priority。这些事实只证明一条隔离转发测试路径，不证明生产主机本地/容器覆盖。

| 角色 | IPv4 | IPv6 |
| --- | --- | --- |
| 主要观察来源 | `192.0.2.10/32` | `2001:db8:1:0:1::10/128` |
| 独立来源对照 | `192.0.2.11/32` | `2001:db8:1:0:1::11/128` |
| 较宽来源贡献 | `192.0.2.0/26` | `2001:db8:1:0:1::/80` |
| 普通目的 | `192.0.2.100/32` | `2001:db8:1:0:2::100/128` |
| NAT 原始 VIP | `192.0.2.101/32` | `2001:db8:1:0:2::101/128` |

可信拓扑设施创建夹具范围，将其绑定到实际 Enforcement 命名空间句柄/身份、临时夹具 epoch、一个 Agent 引用、一个上下文身份/profile、`transit`、`original-destination`、明确目的边界，以及单一 `graceful` 或 `strict` 模式。一个串行协调器拥有该范围/表/mark；不支持并发写入或两个权威来源共享。不同范围/命名空间代表不同 Agent，不承诺全局事务。

发布能力前，预检和初始化须证明转发、夹具链接/路由/地址、所选观察阶段和具体来源/目的可达。验证保护目的不是 Enforcement 本地地址，Netlink 句柄属于同一命名空间，并记录实际观察的原始来源/元组。标签、上下文字符串、目的前缀或 Go 转换成功均不证明转发隔离；每次应用前再次核对夹具身份及所需能力。

桥接仅接受已证明的上下文含义，物理匹配必须位于明确边界内。在内核变更前拒绝 `host-local`、`published-ingress`、DNAT 后匹配、未知/不匹配的 Agent/上下文/网络空间身份、不支持的协议/地址族/处理方式，以及更宽的物理目的集合。不能丢弃字段来适配投影。普通与 NAT 夹具使用不同的明确上下文身份/边界；运行中夹具的上下文含义和处理模式不变。跨上下文的模式/部署迁移不属于首版桥接接受的能力范围。

扩展夹具 TCP/443、TCP/22 监听，保留原有监听。Gitea 形状场景的逻辑 `gitea/https`、`gitea/ssh` 使用相同的物理 443、22 端口，不隐式转成 8000/8001。Echo 数据只验证 L4 可达，不证明 TLS、SSH 认证或 Gitea 授权。独立 UDP 入口使用 UDP/8002。NAT 明确使用原始 TCP/8000、TCP/8001，由现有夹具翻译到 Server/9000；转换保留原始 VIP/端口，不新增产品端口映射字段。

## 3. 转换、所有权与显式时间

私有桥接分开承担三项职责：

1. 候选校验：首次调用 `networkplan.Compile`，之后的完整输入针对夹具已接受计划调用 `networkplan.Replace`，核对同一权威来源和精确夹具事实。任何应用/清理前完成整份候选校验；桥接不重新解释原始 Grant scopes。
2. 纯物化：消费指定时刻的独立 `Projection`/`Inventory`，验证上下文/能力兼容性，转换为 M0 私有夹具数据并保留来源记录 sidecar。
3. 夹具协调：串行执行实际时钟物化、应用/确认、历史维护及可选严格清理。它拥有副作用；转换器不持有命名空间句柄，不读时钟，不建 timer，不调用后端。

接受的物理 tuple 清单有限：普通夹具仅支持声明目的上的 TCP/443、TCP/22、UDP/8002；NAT 夹具仅支持声明 VIP 的原始 TCP/8000、TCP/8001。策略测试前验证对应未过滤监听/转发路径。即使 M0 可以表示，选中端口/tuple 超出已证明清单仍拒绝。原有额外监听只作为未管理对照，不隐式变成产品映射能力。

协议明确映射：`tcp` → 6、`udp` → 17；`PortFirst == PortLast` 等于规划层单端口。保留规范来源/目的前缀与同地址族配对。活跃 Grant 为零时仍保留全部保护匹配。活跃 Grant/Deny 分别进入列表，保持 deny 优先。只有明确永久贡献才生成 M0 零到期时间；bounded 贡献保留原始绝对 ExpiresAt，已到期/未来/已撤销成员不能安装成当前 allow 或 deny。

Sidecar 保留权威来源、逻辑入口、上下文、全部 Binding ID、分域 Grant/Deny ID、来源/匹配、有效期及撤销状态。只有保留全部来源与独立期限影响时，才能对等价物理规则去重；不能按最晚到期合并权限。不规定生产 nftables 布局或容量上限。准备结果、返回结果和历史均独立持有集合。

Inventory 和计划撤回项属于期望状态，不是安装证据。后端须返回实际写入已 ACK 批次的成员回执，并单独列出因到期/亚毫秒过滤而省略的成员。保留原始绝对期限，通过物理规则关联 sidecar 来源；缺失/失败回执不能由期望 Inventory 伪造。某权限在合法原生到期后读回已不存在，并不代表此前未安装：成功批次回执加自有状态确认仍须记录为历史应用，不能抹去该成员。

## 4. 应用、确认与历史保留

仅在绑定的一次性命名空间内使用已有自有 `inet picketx` 表及 `nftbackend.TestMark`；保留无关表/mark/流。夹具 epoch 防止跨实例提供历史，即使 Agent/上下文名称相同。

| 阶段 | 必须行为 |
| --- | --- |
| Prepare | 完整替换/上下文校验，失败不返回部分结果，不变更内核 |
| Materialize | 在协调器串行区内读取新鲜明确时间，生成当前成员，并向后端传绝对期限 |
| Apply | 同一事务提交自有入站策略及 NAT 场景的已知翻译夹具；M0 当前会重建整张自有表 |
| Confirm | 要求成功批次 ACK，读回自有表/链/set 并核对实际发出的物理范围/成员，NAT 场景也确认翻译配置；额外 allow 或观察失败均报错 |
| Record | 在清理前推进已接受计划及已确认应用版本，将实际发出的权限/保护/来源追加到夹具自有历史 |
| Cleanup | strict 模式下针对已确认新策略，仅删除历史自有且已撤回的流，并确认剩余目标为零 |

当前 M0 NAT 测试在 Apply 后单独 flush DNAT。桥接改为在同一待提交自有表事务中追加已声明的夹具翻译，再统一提交，不能让入站策略生效时翻译缺失。保留旧 helper 供现有 M0 测试；私有只追加夹具 helper 不能独立 flush 或添加任意产品策略。准备失败时，重试前须丢弃已排队批次，不能重放残留操作。组合批次失败须同时保留旧入站策略和翻译。

读回考虑原生到期、内核 timeout 舍入和无语义计数器，不要求剩余 TTL 字节完全相同。批次回执本身不是通用并发协调协议；此确认契约依赖测试排他所有权，仍必须发现错误物理范围、缺失必需对象或额外权限状态。读回失败阻断破坏性清理。

累计、去重保留夹具全部确认应用中实际发出的 allow 成员与保护历史。到期或后续应用省略该权限后，仍保留旧绝对期限及来源。未实际发出的未来/撤销/未绑定期望贡献不能进入已安装历史。有限测试夹具内，将必要历史保留到夹具销毁，不能按期限回收，也不能用最新当前投影替换历史。长期运行时的持久历史保留/回收另行设计。

严格清理的 before 来自已确认历史所有权，不是在新时间重新物化旧计划，也不只是最近一次当前活跃快照。after 是在清理时求值的已确认当前策略，包含活跃 deny 优先及全部存续贡献。删除保留 M0 精确 original/reply tuple、zone、地址族和非零 mark 过滤；删除前完成两个地址族 dump，之后确认剩余目标。保留重叠活跃 Grant、其他入口、无关/无 mark 流和其他 mark，禁止 conntrack flush 或按来源大范围删除。

候选被拒不改变确认状态。已知内核事务拒绝保持旧策略，不触发删除。ACK/传输/确认不明确不能证明已回滚：将夹具标为故障，报告应用状态未知，不撤销、不交接成功状态；保留证据，随后仅由设施清理自己的一次性命名空间。桥接不恢复未知生产状态。

新策略确认后，后续清理失败不能回滚它或续期。保留历史，标记清理未完成，记录 selected/deleted/remaining/错误，并允许针对相同已确认所有权显式重试。重试仍需重新计算时间敏感成员、确认当前策略后再删除，不能换成更宽过滤器。缺少必要历史时，精确清理校验失败。

## 5. 未来边界、期限与空所有权

纯转换器不能激活未来权限。增加可取消的**仅测试使用**的边界驱动器：消费计划 NextChange，用标准库 timer 等待，再于新鲜明确时间重新物化/应用，不依赖 Controller。耗时步骤结束后立即处理已过边界，不能等过时或虚构的更晚时间。每次唤醒都在协调器串行区读取最新已接受计划；计划确认变更后替换/取消旧版本 timer，过时事件不能应用捕获的旧计划或重新开放已撤销权限。取消会停止 timer，阻止后续应用。这不引入生产调度服务。

后端实际发送前，在其串行应用路径内，以新鲜时钟从原始绝对到期时间计算剩余原生 timeout；不能使用排队/等锁之前的旧准备时刻、最初完整 TTL，或将过期 bounded 成员转为零。回执注明实际发出成员。慢准备/应用跨过边界时，需重新物化/确认；不能为过期权限重放完整有效期。任何回执/历史/重放都保留原始绝对时间戳。

真实流量检查在绝对边界后使用明确 **1 秒观察窗口**，记录实际首次观察到拒绝/生效的时间。这是测试上限，不是权限延期或纳秒级实施保证。区分无重应用的原生到期测试，与必须主动安装未来 allow/deny 或清理 strict 流的边界驱动测试。延迟应用、临近期限重放须能发现重新续期的访问；时序越界明确失败，不能通过改期限让测试通过。

M0 当前 nftables Apply 和 conntrack Revoke 都拒绝空 Protected，须明确处理空自有期望：

- 不调用非空 Apply，不虚构 wildcard/sentinel 保护入口，不报告无操作成功，不全局 flush。
- 仅删除绑定命名空间中精确自有 `inet picketx` 表，等待 ACK 并读回确认不存在。可信初始空夹具也须确认不存在；无关表和其他 conntrack mark 保留。
- graceful 撤回不删除 conntrack。strict 撤回使用单独、明确、私有的空 after 清理路径，校验非空历史 before 范围及精确 mark，并接受明确空 after 意图；不能放松通用 fixture.Validate，也不能把任意零快照当可信清理授权。
- strict 模式确认历史撤回自有流剩余为零；失败属于清理未完成，不能成功，须保留历史/证据供显式重试。

已知但未选 Agent 的空 Projection 有效；移除的 Agent 在新共享计划中查询会返回未知 Agent 错误，不能把它或任意查询错误解释为空意图。只有已验证的同权威完整替换、候选清单明确不存在绑定 Agent、替换 Withdrawals 中的旧目标，以及协调器保留的夹具身份/历史，共同构成此特定清理情况的依据。已确认过空状态后的重试若没有新撤回目标，使用保留的明确空状态记录和待清理历史。即使新 AgentRefs 没有该 Agent，也须处理撤回/清理；其他查询/校验错误在清理前失败。

解除 Binding 后，入口变为未管理。移除旧 mark conntrack 状态不承诺服务继续被阻断，也不承诺保护本身移除后每个旧 TCP socket 永久终止。旧 ACK/PSH 不能重新获得自有授权的报文断言，只用于 tuple 仍被保护时；空所有权断言改为自有状态不存在、未管理对照保持可用。

## 6. 契约场景与证据

保留 M0 全部 17 项必需场景及原有证据门禁；新增独立命名的桥接必需场景，具体测试名和签名由实施计划确定。每项必需内核场景覆盖 IPv4/IPv6，或明确其适用协议。单元测试可注入副作用验证顺序/失败，但不能证明数据包兼容。

验证类型：`unit` 是纯函数/注入边界测试，`kernel` 是真实特权报文/状态，`both` 要求两者。仅注入失败不能满足内核部分。

| 场景 | 必须证明 | 验证 |
| --- | --- | --- |
| 上下文拒绝 | 主机/发布/DNAT 后/错误命名空间/profile/能力/过宽范围/未证明 tuple 在任何后端动作前被拒 | `unit` |
| 转换与来源记录 | 明确协议/单端口、同地址族前缀、全部 Binding ID 和分域 Grant/Deny ID 保留；仅永久映射到零到期 | `unit` |
| 非法或未生效输入 | 共享层完整校验；未来/撤销/到期权限不生成当前规则；回执列出后端亚毫秒省略 | `both` |
| Gitea 形状的独立期限 | TCP/443、TCP/22，精确来源及宽 CIDR 独立期限保留；自有 tuple 的报文结果与 Core 一致 | `kernel` |
| Deny 与撤销 | 活跃 deny 优先，移除单条贡献仍保留匹配宽前缀/其他 Grant，无关入口/来源对照继续可用 | `kernel` |
| UDP | 生成的 UDP/8002 策略允许授权数据包；保护范围内已撤回自有状态不能绕过当前权限 | `kernel` |
| 原生到期 | 无 Controller/重应用时，新连接在绝对到期后的记录窗口内被拒；graceful 已建立 TCP 保留，直到后续明确 deny/清理 | `kernel` |
| 未来边界 | 驱动器激活未来 allow/deny，移除到期 deny；记录边界/应用/探测时间，过时版本不能重放旧策略，取消后不再应用 | `both` |
| 重放/延迟应用 | 临近到期重建后端及重复应用仍保留原期限；等锁/准备延迟不重启完整 TTL，也不把到期转永久 | `both` |
| 历史严格清理 | 旧发出 allow 在到期、经过后续确认应用及清理失败后仍留在历史 before；重试实际选中并移除现存撤回流 | `both` |
| 严格清理保留 | 重叠活跃 Grant、其他入口、无关/无 mark 流及其他 mark 保留；保护范围内新撤回连接持续被拒 | `kernel` |
| 应用/确认失败 | 不调用撤销器、不错误推进状态；真实非法批次保留旧可达性，模糊应用报告未知 | `both` |
| dump 中断/部分清理 | 初始 dump 不完整时不删除；错误/剩余计数保留，已确认策略不回滚，显式重试可完成 | `both` |
| Binding 所有权 | 两个 Binding 删除一个仍保留保护和剩余来源记录，最后 Grant 删除后仍保护 | `both` |
| 空自有期望 | 最后 Binding/Agent 删除走明确自有表清理；strict 历史 mark 流 Remaining=0，graceful 不删除；未管理对照仍可用 | `both` |
| NAT original/reply tuple | 入站与翻译原子提交；生成的原始 VIP TCP/8000 撤回保留独立授权 TCP/8001；观察翻译后的 Server/9000 reply，精确过滤保留独立映射 | `kernel` |

内核 runner 须在现有一次性命名空间路径编译/执行桥接 integration binary，将其事件纳入必需证据。重复运行先移除旧桥接结果。缺失/重复/失败/跳过必需桥接场景使门禁失败；PICKETX_KERNEL_TESTS=1 下权限/初始化失败须失败，不跳过。单元和特权作业分开，无法运行场景时也保留失败工件。

记录实际 Linux 内核、Go、模块版本、不可变共享版本、夹具 epoch/上下文/命名空间身份、原始元组、逻辑预期、生成物理成员、绝对开始/结束、应用/确认/驱动/探测时间，以及 selected/deleted/remaining。旧 M0 通过不能算作桥接证据；纯测试、转换结果或非特权作业绿色，均不代表此增量内核验收通过。不能把旧测得内核硬编码成新结果。
