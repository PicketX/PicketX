# Agent 同步流基础（M2D1）

本增量实现可嵌入的 Controller gRPC 服务、公开 protobuf 协议和真实线缆测试；PicketXD Provider、运行时配置、持久化/注册和生产监听后续接入，尚不能声明 Controller 已驱动内核执行。

使用已确定的 grpc-go v1.84.0 与官方 protobuf；生成工具固定 protoc 31.1、protoc-gen-go v1.36.11、protoc-gen-go-grpc v1.6.1。协议为 `picketx.agent.v1alpha1.AgentSync/Connect`，Agent 主动建立双向流，首条 Hello 版本必须为 1。alpha 尚无稳定兼容性承诺。

每个服务固定 authority。独立高熵 Token 的 SHA-256 记录绑定唯一 Agent；只接受一条 Bearer metadata，Token 为 32–256 字节无空格可打印 ASCII。身份与权限由服务端推导，不接收客户端指定身份，不保留或记录明文 Token。凭据替换先完整校验再提交；删除、轮换、重绑定立即关闭旧流。同 Agent 新认证流取代旧流。撤销、发布、接入与报告接收串行化；内存状态不构成集群级撤销。

快照只来自已编译 Candidate，含 authority、Agent、正递增 revision、确定性 protobuf 的 SHA-256 和节点完整目标清单。类型化消息保留上下文、地址匹配、能力要求、Binding 来源、未来/过期/撤销的独立 Grant/Deny 与 RFC3339Nano 绝对截止时间，不发送全局配置或其他节点。最后 Binding 删除或 Agent 从配置删除后，仍有有效凭据的节点收到明确空清单。发布重新检查共享替换约束及 UID 种类，避免独立编译绕过改指向限制；无效、回退、超限发布完整拒绝，不改变当前状态。新增凭据也接收当前完整快照。

仅保留最新完整发布，重连重发，慢端合并更新而不积压历史。进程内 revision 严格递增；跨重启持久化单调性由后续权威存储提供。本增量不伪造持久化保证。

报告必须匹配该流最后实际发送的 revision/hash，含合法观测时间及 RECEIVED/APPLIED/FAILED 状态。报告是认证 Agent 的声明，不是 Controller 对内核的证明。分别记录服务器接收时间和 Agent 观测时间，查询返回独立副本；失效旧流不能覆盖新流。拒绝非法报告、重复 Hello 或未知消息，不泄漏内部错误。

显式正数限制包括凭据数、认证并发流、快照字节数（不超过 4 MiB）、每秒接入次数、每流每秒消息数，独立于普通 HTTP。限速为进程本地一秒固定窗口，不是持久化配额。Hello 和发送有正数超时；Close 终止所有流并拒绝新接入。每流固定接收/发送工作协程，RPC 结束时退出，无逐发布协程与无限队列。

包本身不开监听。装配者集中管理 gRPC 生命周期、4 MiB 收发限制，以及可选标准服务端 TLS；明文显式选择且无保密性/服务端认证。TLS 正常校验证书，不跳过验证，不强制 mTLS。测试明文与可信证书 TLS 的真实 protobuf 流。现有仅存活检查的入口本次不改变。
