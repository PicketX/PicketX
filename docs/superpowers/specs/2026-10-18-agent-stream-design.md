# Agent stream foundation (M2D1)

## Goal and scope
Build the Controller-side, embeddable gRPC/protobuf transport now; PicketXD provider integration, operator runtime configuration, persistence/enrollment and production listeners follow separately. This increment has a real generated client/server and wire-level tests. It does not claim Controller-driven kernel enforcement or a deployable Controller Mode.

## Decisions
Use the approved grpc-go v1.84.0 and official protobuf. Pin protoc 31.1, protoc-gen-go v1.36.11 and protoc-gen-go-grpc v1.6.1. Public protocol is `picketx.agent.v1alpha1.AgentSync/Connect`, an Agent-initiated bidirectional stream. This alpha contract is not a stable compatibility promise; reject other protocol versions. No HTTP polling or GPL Agent imports.

A Controller service has one immutable authority identity. A SHA-256 credential record binds one independently revocable, high-entropy bearer Token to exactly one Agent reference; callers cannot choose their identity. Require exactly one `authorization: Bearer <token>` metadata value, 32–256 printable non-space ASCII token bytes. Never retain/log raw Tokens. Validate credential replacements atomically; deleting, rotating or rebinding a record terminates its existing streams. One active stream per Agent; a new authenticated stream supersedes the old stream. Credential revocation and publication are serialized with admission/report acceptance. Process memory is not a cluster-wide revocation mechanism.

A first Hello must contain protocol version 1. Full snapshots contain authority, credential-derived Agent, positive monotonic revision, SHA-256 of deterministic protobuf content and only that Agent's compiled target inventory. Typed protobuf messages retain ownership keys, context, matching destinations, capabilities, binding provenance, future/expired/revoked Grant and Deny contributions and absolute RFC3339Nano deadlines. Contributions are not reduced to a current-time allow set. Every publication replaces a complete snapshot; removing all bindings yields explicit empty inventory. Removed Agents with still-authorized credentials also receive empty inventory. No cross-node payloads or raw global configuration. Invalid candidate/revision/oversize publication changes nothing. Recheck shared replacement/retained UID-kind constraints before publication, so independently compiled candidates cannot bypass retargeting guards. Immutable compiled candidates are the only publication input.

The service retains only the latest complete publication. Reconnection receives it; slow streams coalesce updates instead of accumulating unbounded history. Revisions must strictly increase in process; external authoritative persistence must supply monotonic revisions across restarts. Do not fabricate durable guarantees in this increment. All existing/new credential scopes get a complete current snapshot, including a scope added after publication.

Reports identify the last snapshot actually sent on that stream by revision and hash, with a valid observation timestamp and RECEIVED/APPLIED/FAILED phase. They are authenticated Agent assertions, never Controller proof of kernel execution. Store receive time separately from Agent observation time; latest reports are independently copied, and disconnected/superseded streams cannot overwrite a successor's report. Reject malformed/mismatched reports, duplicate Hello and unsupported message types without exposing internal details.

## Bounds and lifecycle
Explicit positive limits: maximum credential count, concurrent authenticated streams, snapshot bytes (at most 4 MiB), stream establishment attempts per second and messages per stream per second. Limits are independent from ordinary HTTP. Use process-local fixed one-second windows; these are abuse bounds, not durable tenant quotas. gRPC MaxRecvMsgSize/MaxSendMsgSize enforce 4 MiB at transport assembly in tests/integration examples. Hello must arrive within a configurable positive timeout; sends must finish within a positive timeout, so stalled peers do not retain a slot forever. Close terminates sessions and rejects admission. All goroutines exit when RPC returns; no one goroutine per publication or unbounded queues.

The package does not open sockets. Callers centrally own gRPC server/listener lifecycle and optional standard gRPC server-TLS credentials. Plaintext is allowed explicitly at assembly; it has no confidentiality or server authentication. TLS uses normal certificate verification; no insecure verification or mandatory mTLS. Test both plaintext and verified server TLS with real protobuf streams. The current liveness-only executable remains unchanged until runtime configuration and Agent provider integration are ready.

## Acceptance
Wire tests cover scoped snapshots, lossless deadlines/provenance, empty withdrawal, reconnect/coalescing, Token rejection/rotation/revocation, impersonation resistance, stream supersession, report correlation/copy/freshness, atomic publication failures, bounds/timeouts, shutdown and TLS certificate verification. Run all Core tests, race/vet/build/static CLI checks and Web lockfile checks. Fresh whole-branch review precedes merge.
